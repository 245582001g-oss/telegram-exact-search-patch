# v1.0.0 发布验证

验证日期：2026-09-07。所有构建与测试在独立工作目录执行；未启动或控制真实 Telegram，也未读取账号、聊天记录或个人规则文件。

## 可复现构建

本次使用：

- Windows x64；Python 3.12.10。
- `pefile==2024.8.26`；测试使用 `unicorn==2.1.4`。
- GCC 16.1.0，WinLibs MinGW-w64 x86_64 UCRT POSIX SEH r2。
- GNU ld 2.46.0.20260210，Binutils MinGW-w64 x86_64 r2。

公开的 C、头文件、汇编与 hook 清单保持 r3 原始字节，`.gitattributes` 禁止这些构建输入的换行转换。Python 构建器移除了个人路径默认值，改为显式 `--input`；`--gcc` 也可通过 `GCC` 环境变量或 PATH 发现。

公开源码实际重新编译成功，完整输出 SHA-256 与 r3 一致：

```text
894b04982521932a159397872604e0c96c9bd0bd8d48643f4a245899ea0a29c0
```

输入文件的 SHA-256 与有效 Telegram 官方 Authenticode 签名均已核对。构建前后输入保持不变。生成的修改版不具备官方签名。

构建器检查原版哈希、调用点目标、指令字节、PE 节内容、入口点、展开表、重定位和校验和。Windows `SEC_IMAGE` 创建验证通过；这个检查不执行客户端代码。

假输入拒绝验证通过：未知哈希输入返回失败，输入未改动，未创建输出目录。

## 编译后补丁回归

`tests/test_menu_payload.py` 在两个模拟加载地址下执行实际编译出的 Windows x64 指令：`0x140000000` 与 `0x7ff400000000`。

每个地址均通过 **16 组菜单/黑名单/性能回归及 7 组原有搜索回归**，覆盖：

- UTF-16 连续匹配、消息多词组 AND 匹配，以及联系人与用户名过滤。
- 消息、预览、注入结果及无关搜索模式。
- 菜单回调、屏蔽与撤销、存储失败处理及对象生命周期。
- 迁移路径解析、原子存储、长度快速排除与哈希索引。
- 300 ms 防抖指令及调用约定保持。

测试前后完整 EXE 与独立 payload 的哈希一致。`tests/test_payload.py --build-dir build` 也可独立运行原有 7 组搜索回归。

## 工具与公开文件

安装/恢复脚本仅接受兼容性清单中的两个固定哈希，要求显式路径，保留原版备份。黑名单管理脚本使用显式数据库路径，不依赖原工作区的安装清单。

Windows PowerShell 5.1 下的 34 项隔离检查通过，涵盖脚本语法、Status/Undo/Clear、损坏规则文件与锁竞争、无效路径、未知哈希拒绝、模拟进程运行检查、假文件原子替换及备份不覆盖。未对真实 Telegram 目录执行安装或恢复。

发布包按源码白名单组装，排除可执行文件、个人路径报告、账户数据、黑名单、缓存和测试产物。仓库提供 MIT 许可证及上游许可范围说明。

## 验证边界

模拟器使用合成 Qt/Telegram 对象、WinAPI 桩与内存文件系统。因此通过回归不等于完整客户端 GUI 或真实网络测试。实际界面搜索、右键菜单和重启后的效果仍需用户在对应版本自行确认。

本次没有重新测量端到端网络速度，也不宣称网络搜索速度翻倍。所有结果都限于指定的 7.2.5 文件；不能推广为其他 Telegram 版本兼容证明。
