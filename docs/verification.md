# v1.3.0 / Telegram 7.2.8 验证

构建、测试和本机启动检查于 2026-09-17 至 18 日完成。机器可读报告见 [verification.json](verification.json)。

## 程序与适配

输入为官方 Telegram 7.2.8 Windows x64，SHA-256：`4de51db14afe0aace6b38665e1110f0eecb1112c387d44f380236b33d963c13d`。
输出 r5 SHA-256：`8a5fc166834e3e927547b2ad90c88f3578f65d2bce47cd8a522ec270daa0a0f3`。

逐项重映射 7.2.8 内部地址，未沿用固定偏移。保留原有节 RVA、导入表及 ASLR/NX 标志；新增启动桥接先初始化可选规则目录，再跳回原始入口。6 个 CALL hook、1 个 300 ms 防抖字面量及 1 个自动更新默认字节的修改由清单约束，其余原节内容逐字节核对。展开表为 349,580 条原项加 53 条补丁项；无补丁重定位或新增导入。PE 校验和、异常表、重定位等价及 Windows SEC_IMAGE 装载通过。

频道 ABI 对照上游 `data_peer_id.h`、`data_peer.h`、`data_channel.h` 和原版指令：HistoryItem.history +0x10，History.peer +0x2d8，PeerData.id +8；频道类型为高位 2，广播标记位于 +0x1a8 的 1<<10。按完整类型化 ID 筛选，避免同名频道、用户与频道裸 ID 重合导致误屏蔽。

自动更新只修改 gAutoUpdate 的初始数据（RVA 0x8e348c4，01→00）。原生更新检查、开启开关及已保存设置读取指令保持不变。

## 实际编译代码回归

在 `0x140000000`、`0x7ff400000000` 两组加载地址执行编译出的 x64 指令，Qt/WinAPI 以合成对象和受控文件系统替身提供：

- 原有连续文字匹配、多词 AND、名称/别名、范围透传、注入结果、无结果页及容器所有权回归全部通过。
- 菜单连接、排队回调、槽释放、失效行防护、同文屏蔽/撤销、碰撞索引及加载标志回归通过。
- 频道菜单只在广播频道出现；保存固定 ID 后清除菜单上下文、改名、40 条不同长文案仍被正确过滤；同名其他频道和相同裸 ID 的用户不受影响。
- 当前普通/预览结果刷新、未来页/范围搜索/注入过滤、全局频道名称及赞助项销毁、重启读规则和独立撤销均通过。
- 首次空目录、中文/重定向目录、旧规则迁移、已有目标不覆盖、损坏记录不重置、目录拒绝写入仍返回原生入口均通过。
- 多语言正反例每个地址 86 项，包含“好人”“好天气”“好的人”“好 人”、混合文字、emoji、大小写和 Unicode 形式。

此外，外置管理器 94 项、安装/恢复 40 项、PowerShell 差分重建 24 项、Python 差分包 14 项及未知版本拒绝检查通过。规则管理脚本在真实 Windows PowerShell 上以独立假文件验证 Content/Channel 的 Status、Undo、Clear、格式和保留字段校验。
